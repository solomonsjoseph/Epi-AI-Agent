# Cohere Embed v4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver working Cohere Embed v4 packages for both studies and compatible Epi-Agent retrieval.

**Architecture:** Keep provider adapters within their independently deployable repositories. Builders and runtime agree on the compatibility identity, Chroma function name, 1536-dimensional vectors, and document/query input types. Extend the existing profile and package mechanisms rather than creating another retrieval path.

**Tech Stack:** Python 3.12, boto3/botocore, ChromaDB 1.5.8, DuckDB, pytest, FastAPI, Playwright.

## Global Constraints

- Model `cohere.embed-v4:0`, region `us-east-1`, dimensions `1536`, float vectors.
- Index identity `Bedrock/cohere-embed-v4-1536`; Chroma function name `bedrock-cohere-embed-v4`.
- Chroma config keys `model_name`, `region_name`, `dimensions`; credentials never serialized.
- Index with `search_document`, query with `search_query`, maximum batch 96.
- Preserve raw sources, old release archives, decoder `pyreadstat==1.3.7`, and unrelated user edits.
- Existing OpenAI packages and explicit OpenAI configuration remain supported.
- NHANES release `0.4.0`; RePORT release `0.5.0`.
- Real feature smoke runs once, maximum 300 seconds, no provider or production subsystem stubs; preserve evidence on failure.
